# dinorunner-web

Chrome's Dino game running in the browser: libdinorunner's C engine, driven through the
[Rust binding](../../binding/rust) and compiled to WebAssembly.

The page draws the original sprite sheet on a `<canvas>`, plays the original sounds, keeps the
high score in `localStorage` and inverts the canvas in night mode, like the original game.

## Requirements

- Rust with the WebAssembly target:
  ```shell
  rustup target add wasm32-unknown-unknown
  ```
- The `wasm-bindgen` CLI, in exactly the version pinned in `Cargo.toml`:
  ```shell
  cargo install wasm-bindgen-cli --version 0.2.129
  ```
- clang and llvm-ar, to compile the C engine to WebAssembly (gcc cannot):
  ```shell
  sudo apt install clang llvm
  ```
- Python 3, only to serve the page locally.

## Build and run

```shell
./build.sh --serve
```

Then open <http://localhost:8000>. Without `--serve`, the script only builds. `--debug` builds
without optimizations.

The build writes everything the page needs into `www/`:

| Path | Content |
| --- | --- |
| `www/index.html` | The page (tracked in git) |
| `www/pkg/` | The wasm module and its JavaScript glue, generated by `wasm-bindgen` |
| `www/assets/` | Sprite sheet and sounds, copied from `demo/assets` |

`www/` can be published as is on any static web server. The page must be served over HTTP:
browsers do not load WebAssembly modules from `file://` URLs.

## Controls

| Action | Keyboard | Touch / mouse |
| --- | --- | --- |
| Start, jump, restart | <kbd>Space</kbd>, <kbd>↑</kbd> or <kbd>W</kbd> | Tap the game |
| Duck, drop faster while jumping | <kbd>↓</kbd> or <kbd>S</kbd> | |

Releasing the jump key early makes a lower jump.

## How it works

`src/lib.rs` implements the binding's `dinorunner::Platform` trait for the browser:

| Engine request | Browser API |
| --- | --- |
| `timestamp` | `performance.now()` |
| `clear_canvas`, `draw` | Canvas 2D context, cutting sprites out of the sprite sheet |
| `play_sound` | `HTMLAudioElement` |
| `vibrate` | `navigator.vibrate()` |
| `read_high_score`, `write_high_score` | `localStorage`, key `dinorunner-high-score` |
| `log` | `console.log()` |

The game starts once the sprite sheet is loaded. A `requestAnimationFrame` loop then calls
`Dinorunner::update` once per displayed frame. Night mode is not drawn by the engine: the loop
toggles the `inverted` CSS class on the canvas, which applies `filter: invert(1)`.

The binding's build script compiles the C sources from `dinorunner/` directly, so the C library
does not need to be built with CMake first. `wasm32-unknown-unknown` has no C standard library,
which the engine does not need: it formats its log messages itself.

## Troubleshooting

**`clang not found`**: install clang and llvm, see [Requirements](#requirements). To use another
compiler, set `CC_wasm32_unknown_unknown` (and `AR_wasm32_unknown_unknown`) before running
`build.sh`.

**`wasm-bindgen` reports a version or schema mismatch**: the CLI and the `wasm-bindgen` crate
versions differ. Install the CLI version pinned in `Cargo.toml`.

**No sound**: browsers block audio until the first interaction with the page. The first key
press starts the game and unlocks sound from then on.

**The high score is not kept**: `localStorage` can be unavailable, e.g. in private windows of
some browsers. The game still runs, without storing the high score.
